──────── Project Summary ────────

### Top Issues

1. **State overwrite race in board refresh logic** — `doc2video/backlot/ui/board.js`  
   SSE-driven `refresh()` calls have no request sequencing or abort handling, so overlapping responses can resolve out of order and overwrite newer state with older state. This is likely the most user-visible correctness issue because it can cause the board to flicker back to stale stage state.

2. **Fragile data normalization can crash the UI** — `doc2video/backlot/ui/board.js`  
   `normalize()` is meant to tolerate sparse/legacy payloads, but it dereferences scene entries without null safety. A malformed `storyboard.scenes` array can throw inside `normalize` before render, defeating the purpose of the defensive layer.

3. **Audio format assumptions are unsafe** — `doc2video/audio.py`  
   The code assumes 16-bit PCM without validating sample width or compression type. Float or compressed WAV inputs can be misinterpreted, leading to corrupted or incorrectly shaped audio data. This is a correctness issue that can propagate silently.

4. **Replay mode is not robust across browser environments** — `doc2video/backlot/ui/board.js`  
   Use of `structuredClone` without fallback will fail in older Safari and can leave the page in a dark/unresponsive state from a button click. This is both a compatibility bug and a failure-mode issue.

5. **UI can render in a confusing or broken state** — `doc2video/backlot/ui/board.js`, `doc2video/backlot/ui/board.html`  
   There are several concrete rendering issues: an unconverted JSX-like expression producing malformed output, a timestamp printed as raw ISO in one place, and a range slider whose `min`/`max` are not actually bound, causing incorrect clamping behavior.

6. **Accessibility and semantic HTML gaps in modals** — `doc2video/backlot/ui/board.html`  
   The modal backdrop lacks proper dialog semantics (`role="dialog"`, `aria-modal`, hidden state), which can mislead assistive technologies and cause focus/announcement issues.

7. **Poor no-JS or failed-load experience** — `doc2video/backlot/ui/board.html`  
   If JavaScript is disabled or fails to load, the page can appear completely blank with no diagnostic. This makes debugging and first-run experience worse.

8. **Dead or incomplete layout parameter** — `doc2video/backlot/ui/board.js`  
   The `vertical` parameter is never effectively used, suggesting an unimplemented shorts/vertical layout or leftover API surface. This is a maintenance hazard if readers assume it works.

9. **Misleading stylesheet scope** — `doc2video/backlot/ui/index.html`  
   The Library page reuses `board.css`, which suggests board-specific styling while actually containing library-page styles. This will mislead future maintainers about where `.lib-grid` and `.lib-card` rules live.

10. **Inconsistent import and utility usage patterns** — `doc2video/audio.py`, `doc2video/backlot/ui/board.js`  
   There is inconsistent handling of stdlib imports and formatting helpers. In particular, `math` is imported locally while other stdlib modules are top-level, and timestamp formatting is applied inconsistently across the board UI.

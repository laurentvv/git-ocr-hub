## 2. Synthèse de l'Audit OpenCodeReview (15 Findings)

### 🔴 Sécurité (2 findings)

#### 1. `projects/P-29_hq_workflows/dashboard/index.html:35`
- **Gravité** : Medium
- **Description** : Les noms de fichiers de rendu sont concaténés sans échappement dans l'attribut HTML et dans le gestionnaire `onclick` (`src="../renders/${r}" onclick="zoom(this.src)"`). Un nom de fichier contenant des guillemets ou des balises HTML (`</img>` ou `<script>`) permet une injection HTML/JS (XSS).
- **Correctif recommandé** : Utiliser la fonction d'échappement existante `esc()` avant l'injection dans le template HTML.

#### 2. `projects/P-29_hq_workflows/dashboard/index.html:36`
- **Gravité** : Medium
- **Description** : `a.id` est inséré sans échappement dans le balisage (`onclick="set('${a.id}',...)"`, `cm('${a.id}',...)` et dans le libellé `- ${a.id}`), alors que les autres champs sont échappés. Si un identifiant contient un guillemet ou des caractères spéciaux, cela corrompt le DOM et expose à une injection.
- **Correctif recommandé** : Échapper systématiquement `a.id` avec `esc(a.id)`.

### 🟠 Bugs & Erreurs d'Exécution (5 findings)

#### 3. `scripts/img2render.py:75`
- **Gravité** : Medium
- **Description** : Défaut de logique booléenne dans la condition d'exemption GPU : `if used > ns.max_vram_mb and not (ns.skip_trellis and ns.stop_after_cutout):`. Le script s'arrête immédiatement après le découpage dès que `--stop-after-cutout` est actif. L'option recommandée dans la docstring pour inspecter le découpage sans GPU échoue donc avec "GPU busy".
- **Correctif recommandé** :
  ```diff
  - if used > ns.max_vram_mb and not (ns.skip_trellis and ns.stop_after_cutout):
  + if used > ns.max_vram_mb and not ns.stop_after_cutout:
  ```

#### 4. `scripts/tools/install_extdeps.py:69-71`
- **Gravité** : Medium
- **Description** : L'extraction de l'archive wheel n'est réalisée que lors du téléchargement initial. Si `dest` existe déjà, les exécutions ultérieures passent à la suite avec `continue`. En cas d'interruption entre le renommage et l'extraction (disque plein, Ctrl+C), le répertoire extdeps reste incomplet et n'est jamais réextrait.
- **Correctif recommandé** : Toujours vérifier la présence des fichiers décompressés ou exécuter `extractall` de façon idempotente.

#### 5. `scripts/tools/install_extdeps.py:60-61`
- **Gravité** : Medium
- **Description** : `urllib.request.urlretrieve` n'est protégé par aucun bloc `try/except`. Une instabilité réseau ou une erreur HTTP interrompt brutalement l'ensemble du script au lieu d'enregistrer l'échec et de passer aux paquets suivants.
- **Correctif recommandé** : Encapsuler la boucle de téléchargement dans un `try/except (URLError, OSError, BadZipFile)` avec nettoyage du fichier temporaire `.part` et flag `failed = True`.

#### 6. `projects/P-29_hq_workflows/dashboard/index.html:40`
- **Gravité** : Medium
- **Description** : `navigator.clipboard` n'est disponible que dans un contexte sécurisé (HTTPS / localhost). Ouvrir le dashboard via le protocole `file://` déclenche une `ReferenceError` non interceptée lors du clic, et un refus de permission génère une promesse non capturée.
- **Correctif recommandé** : Ajouter un wrapper avec fallback sur `document.execCommand('copy')` et gestion `.catch()`.

#### 7. `projects/P-24_scene_nature/scripts/p24_render.py:46`
- **Gravité** : Low
- **Description** : Le répertoire `renders/` n'est jamais créé préalablement via `os.makedirs(..., exist_ok=True)`. Sur un clone propre sans dossier `renders/` existant, le script échoue avec une erreur I/O. De plus, le séparateur `\` en dur est spécifique à Windows.
- **Correctif recommandé** :
  ```python
  renders_dir = os.path.join(P24, "renders")
  os.makedirs(renders_dir, exist_ok=True)
  sc.render.filepath = os.path.join(renders_dir, f"{name}.png")
  ```

### 🟡 Performance & Fuites (1 finding)

#### 8. `projects/P-29_hq_workflows/dashboard/index.html:43` & `index.html:48`
- **Gravité** : Low
- **Description** : 
  - `set()` appelle `save()` (qui appelle `sum()`), puis `render()` (qui réappelle `sum()` et reconstruit l'intégralité du DOM `innerHTML`).
  - L'URL de l'objet Blob téléchargé n'est jamais libérée via `URL.revokeObjectURL(u)`, provoquant une fuite mémoire par clic d'export.
- **Correctif recommandé** : Éviter les recalculs en doublon et ajouter `URL.revokeObjectURL(u)`.

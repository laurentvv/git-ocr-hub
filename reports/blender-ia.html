🛡️ 1. Sécurité & Injections (2 anomalies)

projects/P-29_hq_workflows/dashboard/index.html:35 Sécurité · Medium
Les noms de fichiers de rendu sont concaténés sans aucun échappement dans l'attribut HTML et le gestionnaire onclick (src="../renders/${r}" onclick="zoom(this.src)"). Si un nom de fichier contient des guillemets ou une balise HTML, cela provoque une injection de code (XSS).
Correctif : Échapper la variable avec la fonction esc() déjà définie dans le projet : src="../renders/${esc(r)}" onclick="zoom(this.src)"
projects/P-29_hq_workflows/dashboard/index.html:36 Sécurité · Medium
a.id est injecté sans échappement dans le DOM (onclick="set('${a.id}',...)" / cm('${a.id}',...) et le libellé - ${a.id}), alors que les autres champs sont échappés. Risque de cassure du balisage ou d'injection si un identifiant d'asset contient des caractères spéciaux.
Correctif : Appliquer esc(a.id) uniformément sur tous les points d'insertion dans le template.

🐛 2. Bugs & Défaillances Logiques (5 anomalies)

scripts/img2render.py:75 Bug · Medium
Défaut de logique booléenne dans la condition d'exemption VRAM : la condition actuelle exige à la fois --skip-trellis et --stop-after-cutout. Pourtant, le pipeline s'arrête systématiquement après le découpage dès que --stop-after-cutout est actif. Le mode recommandé dans la doc pour vérifier le cut sans GPU plante donc avec "GPU busy".
- if used > ns.max_vram_mb and not (ns.skip_trellis and ns.stop_after_cutout): + if used > ns.max_vram_mb and not ns.stop_after_cutout:
scripts/tools/install_extdeps.py:69-71 Bug · Medium
L'extraction de l'archive wheel n'est réalisée que lors du premier téléchargement. Si le fichier zip dest existe déjà, les exécutions ultérieures le sautent via continue. En cas d'interruption (disque plein, crash, Ctrl+C) entre le téléchargement et l'extraction, le dossier extdeps reste incomplet et n'est jamais réextrait.
Correctif : Rendre l'extraction systématique (idempotente) ou valider la présence des artefacts décompressés.
scripts/tools/install_extdeps.py:60-61 Bug · Medium
urllib.request.urlretrieve n'est pas protégé par un bloc d'interception d'exceptions. Une erreur réseau ou timeout fait crasher l'intégralité du script au lieu d'enregistrer l'échec et de passer aux paquets suivants.
Correctif : Entourer d'un try/except (URLError, OSError, BadZipFile), supprimer le fichier partiel .part et continuer.
projects/P-29_hq_workflows/dashboard/index.html:40 Bug · Medium
L'API navigator.clipboard n'est disponible que dans un contexte sécurisé (HTTPS / localhost). Ouvrir ce dashboard localement via file:// lève une ReferenceError bloquante au clic.
Correctif : Ajouter un fallback sur document.execCommand('copy') avec gestion .catch().
projects/P-24_scene_nature/scripts/p24_render.py:46 Bug · Low
Le dossier de sortie renders/ n'est jamais créé préalablement via os.makedirs(..., exist_ok=True). Sur un environnement propre sans dossier de rendu existant, le script échoue. De plus, les séparateurs d'antislashs sont spécifiques à Windows.
renders_dir = os.path.join(P24, "renders") os.makedirs(renders_dir, exist_ok=True) sc.render.filepath = os.path.join(renders_dir, f"{name}.png")

⚡ 3. Performance & Optimisations (1 anomalie)

projects/P-29_hq_workflows/dashboard/index.html:43 & 48 Performance & Fuite
1. set() appelle save() (qui appelle sum()), puis render() (qui rappelle sum() et réécrit l'intégralité du DOM innerHTML).
2. L'URL d'objet Blob générée pour le téléchargement n'est jamais révoquée via URL.revokeObjectURL(x.href), créant une fuite mémoire à chaque export.
